### 3-3. A에게 요청하는 것

**(1) `LocalDataInitializer`에 `@Order(0)` — 우선순위 높음**

순서 지정이 없어 `LOWEST_PRECEDENCE`로 잡히는 바람에, B의 `local` 시드가 A의 사용자·과정 시드보다 **먼저** 실행됩니다. **시험·과제·공지·Q&A·설문 다섯 슬라이스가 연속으로** 같은 함정을 밟았고, 공지에서는 시드가 통째로 실행되지 않고 있었습니다. B는 `@EventListener(ApplicationReadyEvent.class)`로 우회했지만 근본 해결은 A쪽입니다.

**(2) `CourseQueryService` 조회 4종 추가**

| 메서드 | 없을 때 문제 |
|---|---|
| `findCourseIdsByInstructorId(userId)` | 지금은 전체 과정 훑고 `isInstructorOf`를 과정마다 호출 → **쿼리 N+1** |
| `findAllCourseOptions()` | 과정 셀렉트가 필요한 화면마다 우회 코드 중복 |
| `findUserDisplays(userIds)` | `findUserIdsByCourseId`가 id만 줘서 화면에 이름 표시 불가 |
| `findInstructorsByCourseId(courseId)` | 채점자 지정 셀렉트. 지금은 `findAll()` 후 자바 필터링 |

들어오면 B쪽 우회 코드(`AssignmentLookupRepository`, `SurveyService.courseOptions()` 등)를 전부 걷어냅니다.

**(3) 공통 `@ControllerAdvice` 소유자 확정**

삭제된 리소스 URL 직접 접근 시 `IllegalArgumentException`이 그대로 올라가 **whitelabel 500**이 뜹니다(404가 맞음). 개별 도메인이 아니라 공통에서 처리해야 일관됩니다. 공통 파일이라 B가 단독으로 만들지 않았습니다.

**(4) Apache POI 도입 동의 여부**

`build.gradle`은 공동 소유라 B가 못 건드립니다. POI를 넣으면 **G-5·H-4·I-1·J-8 네 항목이 동시에 해소**됩니다(리포트 §5-1 지적과 동일). 동의하시면 A가 추가해 주세요.

**(5) 공유 파일 수정 통지**

B가 아래를 수정했습니다. 전부 하위호환이라 A 쪽 화면은 그대로 동작합니다.

- `static/js/contents.js` — 더미 배열을 `window._serverContentRows || [기존 더미]`로. A의 `trainee/contents.html`·`instructor/contents.html`·`courses-detail.html` 영향 없음
- `static/js/assignments.js`, `assignments-grading.js` — 동일 방식
- `templates/fragments/{admin,instructor,trainee}.html` — **B 도메인 메뉴 링크만** 컨트롤러 URL로 교체(23곳). A 영역(대시보드·사용자·과정·출결·이수)은 정적 경로 그대로 뒀습니다
- `application-dev.yml` — `spring.sql.init` + `defer-datasource-initialization` 추가 (PostgreSQL 부분 유니크 인덱스 적용용)

**(6) `dev` 프로필 초기 계정 문제**

`LocalDataInitializer`가 `@Profile("local")`이라 **PostgreSQL로 띄우면 계정도 과정도 없는 빈 DB로 시작**합니다. 운영 전에 초기 관리자 계정 생성 방법을 정해야 합니다.

## 4. 에스컬레이션 — 자체 구현이 비현실적인 7개 항목

`앨리스 항목.hwp`는 **엘리스가 자사 플랫폼을 설명한 문서**입니다("세종교육은 엘리스 LXP 플랫폼을 **대여**하여 세종교육에 맞춰 수정 및 개선하여 운영"). 그래서 아래는 우리가 직접 만들 수 있는 성격이 아니고, **개발 일정으로 잡으면 안 되는 항목**입니다.

| 항목 | 리포트 ID | 왜 어려운가 |
|---|---|---|
| 3중 모니터링 (웹캠·모니터·모바일) | G-4 | WebRTC 미디어 서버(SFU) 필요. 현재 카메라 타일은 서버 데이터를 얹은 **자리표시자** |
| 원격 신분증 확인 (QR) | G-8 | 모바일 업로드 + 운영진 승인 플로우 + 개인정보 마스킹 |
| 컴퓨터 환경 강제 통제 | G-9 | 화면·웹캠 강제 공유, 듀얼 모니터 차단 — 브라우저 권한 한계 |
| 화상강의 2,000명 동접 | J-6 | Zoom 등 외부 연동이 현실적 |
| 브라우저 IDE / 100+ 언어 | J-2 | Monaco·Jupyter급 실행 샌드박스 |
| 안면인식 출석 | J-9 | 외부 솔루션 |
| 오토스케일링 / NIPA 인증 / 특허 | — | **엘리스사 자산.** 우리 산출물이 될 수 없음 |

**세 갈래 중 하나를 기관과 정해야 합니다:**

1. 해당 항목은 **엘리스 플랫폼을 실제로 대여**해서 충족 (문서 그대로)
2. **외부 솔루션 연동**으로 대체 (Zoom, PASS 본인인증, 안면인식 SaaS 등)
3. 내역서에서 **해당 항목을 제외**하고 제출

이게 정해져야 남은 일정이 확정됩니다. 개발로 풀 수 있는 문제가 아니라 **계약·범위 결정 사항**입니다.
