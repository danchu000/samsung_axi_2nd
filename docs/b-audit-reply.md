## 3. A에게 요청하는 것 4건

요구사항 해석이 아니라, **A 소유 파일이라 B가 못 하는 것**들입니다.

### 3-1. `LocalDataInitializer` 에 `@Order(0)` — 우선순위 높음

순서 지정이 없어 `LOWEST_PRECEDENCE` 로 잡히는 바람에, B의 `local` 시드가 A의 사용자·과정 시드보다 **먼저** 실행됩니다.
**시험·과제·공지·Q&A·설문 다섯 슬라이스가 연속으로** 같은 함정을 밟았고, **공지에서는 시드가 통째로 실행되지 않고 있었습니다**(`admin 계정이 없다` 경고 후 조용히 종료).

B는 `@EventListener(ApplicationReadyEvent.class)` 로 우회했지만, 새 슬라이스마다 이 함정을 알고 있어야 하는 구조입니다. 근본 해결은 A쪽입니다.

### 3-2. `CourseQueryService` 조회 4종 추가

| 메서드 | 없을 때 문제 |
|---|---|
| `findCourseIdsByInstructorId(userId)` | 전체 과정을 훑고 `isInstructorOf` 를 과정마다 호출 → **쿼리 N+1** |
| `findAllCourseOptions()` | 과정 셀렉트가 필요한 화면마다 우회 코드 중복 |
| `findUserDisplays(userIds)` | `findUserIdsByCourseId` 가 id만 줘서 화면에 이름 표시 불가 |
| `findInstructorsByCourseId(courseId)` | 채점자 지정 셀렉트. 지금은 `findAll()` 후 자바 필터링 |

들어오면 B쪽 우회 코드(`AssignmentLookupRepository`, `SurveyService.courseOptions()` 등)를 전부 걷어냅니다.

### 3-3. 공통 `@ControllerAdvice` 소유자 확정

삭제된 리소스 URL 직접 접근 시 `IllegalArgumentException` 이 그대로 올라가 **whitelabel 500** 이 뜹니다(404가 맞음).
레퍼런스 패턴(`QuestionService`)도 같은 방식이라 개별 도메인이 아니라 공통에서 처리해야 일관됩니다. 공통 파일이라 B가 단독으로 만들지 않았습니다.

### 3-4. Apache POI 도입 동의 여부

`build.gradle` 은 공동 소유라 B가 못 건드립니다. POI를 넣으면 **G-5·H-4·I-1·J-8 네 항목이 동시에 해소**됩니다(리포트 §5-1 지적과 동일). 현재는 CSV로 대체해 뒀습니다.

## 4. 통지 — B가 수정한 공유 파일

전부 하위호환이라 A 쪽 화면은 그대로 동작합니다.

| 파일 | 변경 |
|---|---|
| `static/js/contents.js` | 더미 배열 → `window._serverContentRows \|\| [기존 더미]`. A의 `trainee/contents.html`·`instructor/contents.html`·`courses-detail.html` 영향 없음 |
| `static/js/assignments.js`, `assignments-grading.js` | 동일 방식 |
| `templates/fragments/{admin,instructor,trainee}.html` | **B 도메인 메뉴 링크만** 컨트롤러 URL로 교체(23곳) + "시험 관리" 항목 신설. A 영역(대시보드·사용자·과정·출결·이수)은 정적 경로 유지 |
| `application-dev.yml` | `spring.sql.init` + `defer-datasource-initialization` 추가 (PostgreSQL 부분 유니크 인덱스용) |

**추가 확인 필요:** `LocalDataInitializer` 가 `@Profile("local")` 이라 **PostgreSQL(dev)로 띄우면 계정도 과정도 없는 빈 DB로 시작**합니다. 운영 전에 초기 관리자 계정 생성 방법을 정해야 합니다.

## 5. 참고 — 실행 검증에서 나온 결함

정적 분석으로는 안 잡히는 유형이라 공유합니다. 전부 수정 완료.

- **`ExamAttempt.passed` 가 절대 `null` 이 되지 않았음** → 채점 전 응시가 전부 `false`(불합격)로 저장. **A의 이수 판정으로 넘어가면 수료 대상자가 탈락 처리될 수 있는 문제**였습니다
- **강사가 URL만 바꾸면 담당 아닌 과정의 응시자 명단 노출** → 목록 조회에 권한 체크 누락
- **응답이 200인데 HTML이 중간에 잘려 나감** (`th:if`/`th:each` 평가 순서) → 예외가 삼켜져 로그에도 안 남음
- **문제 코드 채번이 soft delete된 코드를 재발급** → 유니크 제약 위반 예약 상태였음
- `@SQLDelete` 와 유니크 제약 병용 충돌 3건 (과제·설문·문제은행) → PostgreSQL 부분 유니크 인덱스로 정리
