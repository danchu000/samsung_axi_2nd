## 1. 훈련생 학습관리 시스템

### 평가 내용 (양식 요건)
- (정보제공) 훈련생 초기화면에 훈련생 유의사항 등재
- (수강신청) 성명·훈련과정명·훈련개시/종료일·최초/마지막 수강일 등 수강 신청 현황 웹 조회
- (본인인증 및 개인정보) 본인인증 기능, 개인정보 수집 및 제3자 정보제공 안내

### 작성 내용 (구현 현황)

**정보제공**
- 훈련생 모듈 초기화면 및 공지사항 기능 구현 완료(공지 등록·조회·알림). 훈련생 유의사항은 공지사항으로 등재하는 방식으로 운영 예정.

**수강신청**
- 관리자 과정 개설 → 훈련생 수강신청 → 관리자 승인 흐름 구현 완료.
- 훈련생 "나의 과정"에서 과정명·훈련 개시/종료일 등 수강 현황 웹 조회 가능.
- 학습 접속 이력(access_log)을 초기 설계부터 기록하고 있어 최초/마지막 수강일 조회 근거 데이터 확보됨.

**본인인증 및 개인정보**
- 로그인 기반 본인인증 + **평가 응시(시험 입장) 시 재인증** 단계 구현 완료(`IdentityVerificationService`).
- 회원가입(훈련생/강사) 화면에 **개인정보 수집·이용 동의 및 제3자 제공 안내** 절차 포함, 동의 여부를 서버(User 엔티티)에 저장.
- ※ 휴대폰 본인확인 등 외부 본인인증 연동(PASS/아이핀 등) 도입 여부: **미정** (현재는 계정 비밀번호 재확인 방식)

## 2. 평가 및 수료기준

### 평가 내용 (양식 요건)
- 시험·과제 작성 및 평가결과 등 평가 관련 자료 웹 조회
- 진행단계평가·최종평가·과제응시 등 평가유형별 본인인증
- 수료기준이 학습목표 달성 여부를 판단할 수 있도록 적정할 것

### 작성 내용 (구현 현황)

**평가**
- 문제은행·시험 생성/설정(제한시간 등)·응시·답안 제출까지 구현 완료.
- 과제 등록·제출·피드백 구현 완료.
- 채점/성적 조회(GradeQueryService) 구현 완료 — 훈련생이 평가 결과를 웹에서 조회 가능.
- **평가유형별 본인인증**: 시험 응시 입장 시 본인인증 단계를 거치도록 구현 완료(응시 데이터에 본인인증 플래그 저장).

**수료기준**
- 과정별 이수 기준 설정 기능 구현 완료(진도율·성적 요건 등 기준값을 관리자가 설정).
- 출결·진도·성적을 종합한 **자동 이수 판정** 및 **이수증(수료증) PDF 발급** 구현 완료.
- 성적 요건 판정은 채점 도메인(GradeCompletionProvider 어댑터)과 연동되어 학습목표 달성 여부를 데이터 기반으로 판단.

## 3. 전산시스템

### 평가 내용 (양식 요건)
- 훈련별 데이터의 독립적 수집 여부
- 안정성과 확장성을 가진 Web·DB·동영상 서버의 적절성
- 보안관리 적절성

### 작성 내용 (구현 현황)

**훈련별 데이터 독립적 수집**
- 모든 학습 데이터(수강신청·진도·출결·평가·이수)가 과정(course) 단위 식별자로 분리 수집되도록 DB 스키마 설계·구현 완료.

**데이터 보존(최소 3년)**
- 전 엔티티 soft delete(`@SQLDelete` + `@SQLRestriction`) 적용 — 삭제 시에도 데이터가 물리 삭제되지 않고 보존됨.
- 접속 이력·조회 이력 등 로그 테이블을 개발 초기부터 기록.
- 백업을 포함한 3년 보존 운영 정책 문서: **미작성 (서버 환경 확정 후 작성 예정)**

**서버 안정성·확장성 (Web/DB/동영상 서버)**
- 배포 환경은 **온프레미스(사내 서버, Ubuntu) 확정**. 다만 서버 하드웨어 사양·구성(대수, Web/DB 분리 여부)·처리시간·장애 회복 정책 증빙은 **미정** — 장비 확정 후 작성. 붙임의 서버 사양표 참조.

**보안관리**
- 구현 완료(애플리케이션 수준):
  - 비밀번호 bcrypt 해시 저장 (Spring Security)
  - 개인정보 컬럼(전화번호·이메일·생년월일 등) **AES-256/GCM 암호화** — JPA `AttributeConverter`(`CryptoConverter`)로 저장 시점부터 암호화, DB 조회 시 암호문으로 표시됨
  - 역할(관리자/교강사/훈련생) 기반 접근 제어, 로그인 실패 처리, 접속 로그 기록
- 미정(인프라 수준 — 배포 시 적용 예정):
  - SSL/TLS(보안서버) 적용: **미적용 (배포 시 적용 예정)**
  - 서버 백신·보안 소프트웨어, 방화벽/IPS/웹방화벽: **미정**
  - 주기적 보안점검·긴급상황 대응체계 문서: **미작성**

# 붙임. K-디지털 트레이닝 LMS 등 훈련인프라 내역

> ⚠️ 배포 방식은 **온프레미스(사내 서버, Ubuntu) 확정**. 서버 하드웨어 사양·네트워크·보안 장비 등 세부 내역은 장비 확정 후 채운다. 현재 확정: 온프레미스 구축, OS(Ubuntu), DBMS(PostgreSQL), 애플리케이션 수준 암호화.

## [서버 사양] — **하드웨어 사양 미정** (온프레미스 자체 구축 확정)

| 구분 | Web 서버 | 동영상서버 | DB서버 | 백업서버 |
|---|---|---|---|---|
| 확보(대수) | 미정 | 미정 | 미정 | 미정 |
| CPU | 미정 | 미정 | 미정 | 미정 |
| Memory | 미정 | 미정 | 미정 | 미정 |
| HDD | 미정 | 미정 | 미정 | 미정 |
| RAID | 미정 | 미정 | 미정 | 미정 |
| 기타 | 미정 | 미정 | 미정 | 미정 |

- 온프레미스 자체 구축이므로 실제 장비 확보 후 사양(대수·CPU·Memory·HDD·RAID) 기재 예정.
- 네트워크 구성도·서버 사진(IP 식별 가능): **없음 (구축 후 첨부)** — 온프레미스는 실물 서버 사진 촬영 필요.
- ※ 여기서 미정인 것은 서버 **하드웨어 사양**이다. DB서버에 탑재할 DBMS는 **PostgreSQL로 확정** (아래 [DBMS] 항목 참조).

## [전산 장비] — **자체 구축 확정, 세부 미정**
- IDC 서비스·호스팅 계약: **해당 없음** (사내 온프레미스 자체 구축).
- 장비구매(임대) 계약·네트워크(회선) 계약 내용: **미정** — 사내 기존 장비 활용인지 신규 구매인지 확정 후, 구매(임대) 계약서 또는 자산 내역으로 증빙.

## [백업 정책] — **미작성 (계획만 수립)**
- 계획: `pg_dump` 기반 DB 일 단위 자동 백업(cron) + 별도 저장매체(백업서버/외장 스토리지) 보관, 웹로그 보관, 백업 일지·대장 양식, 장애대응 프로세스 도표.
- 현재 증빙물: 없음. 서버 구축 후 스크립트 구축 및 일지 작성 시작 예정.

## [보안 관련] — **미정**
- 보안서버(SSL) 설치 확인서: 없음 (배포 시 적용 후 발급)
- 온프레미스 구축이므로 클라우드 보안그룹 갈음 불가 → 다음을 자체 구성·증빙 필요:
  - OS 방화벽(Ubuntu ufw/iptables) 설정 내역
  - 서버 백신·보안 소프트웨어(예: ClamAV 등) 설치 확인
  - 침입방지시스템(IPS)/웹방화벽(예: ModSecurity 등 WAF) 구성: **미정**

## [DB 서버 (HA)] — **미정**
- 계획: PostgreSQL **streaming replication**(Primary-Replica)으로 사내 서버 2대 구성 (온프레미스이므로 클라우드 Multi-AZ 옵션은 해당 없음).
- HA 확인서·구성도: 없음 (구축 후 작성)

## [DBMS] — **확정**
- DBMS: **PostgreSQL** (오픈소스, PostgreSQL License — 라이선스 문서로 증빙 예정)
- OS: **Ubuntu 확정** (오픈소스, GPL 등 자유 라이선스 — 버전은 미정, LTS 권장. 라이선스 문서로 증빙 예정)

## [DNS 환경] — **미정**
- 도메인 미확보, DNS 설정 스크린샷·IP 주소 없음. 도메인 확보 후 첨부.
- 온프레미스이므로 **고정 공인 IP(회선) 확보** 필요 — 사내 인터넷 회선의 고정 IP 여부 확인 필요.

## [무정전 전원장치(UPS)] — **증빙 필요 (미확보)**
- 온프레미스 자체 구축이므로 "IDC 서비스 이용 시 제외" 조항을 **적용할 수 없음** → UPS 확보 후 제원 증빙 자료 첨부 필요.
- 현재 확보 여부: **미정.**

## [암호화] — **구현 완료 (증빙 스크린샷은 추후)**
- 알고리즘: 개인정보 컬럼 **AES-256/GCM/NoPadding** (IV 12byte + 인증태그, Base64 저장), 비밀번호 **bcrypt** 해시, 전송구간 TLS(배포 시).
- DB 암호화 스크린샷: **미촬영** — 운영 DB 구성 후 암호문 조회 화면 + 알고리즘 명세 첨부 예정.

## [LMS 플랫폼] — URL **미정 (경로 구조는 확정)**

| 구분 | URL |
|---|---|
| 훈련생 모듈 | 미정 — `https://(도메인 미정)/trainee/...` |
| 훈련교사 모듈 | 미정 — `https://(도메인 미정)/instructor/...` |
| 관리자 모듈 | 미정 — `https://(도메인 미정)/admin/...` |

- 모듈별 경로 구조(`/trainee`, `/instructor`, `/admin`)는 구현 완료. 도메인 확보·배포 후 실제 URL 기재.

## 미정 항목 요약 (확정 필요 순)

> 배포 환경은 **온프레미스(사내 서버, Ubuntu)로 확정됨** (2026-07-27). 이제 남은 것은 장비·회선·보안 구성의 세부 확정.

1. **서버 장비 확정** — 대수(Web/DB/동영상/백업 분리 여부), CPU·Memory·HDD·RAID 사양, 신규 구매 vs 기존 장비 활용. HA(DB 2대)와 백업용 저장매체까지 고려해 산정.
2. **UPS 확보** — 온프레미스라 제외 불가, 제원 증빙 필요.
3. **고정 공인 IP 회선 + 도메인 확보** → DNS 설정.
4. SSL/TLS 적용 및 보안서버 확인서, 방화벽(ufw)·백신·IPS/WAF 구성.
5. DB HA(streaming replication) 구성 + 백업 스크립트/일지.
6. 각종 스크린샷 증빙(DB 암호화, 보안 설정, DNS, 서버 실물 사진·네트워크 구성도) — 구축 후 일괄 촬영.
7. 신청기관명·제출일 기재, 장비 구매(임대) 계약서 사본 수급.
