## 기능 1 — AI 기반 직무 로드맵

**화면** `/trainee/ai/roadmap` · **코드** `static/js/trainee/ai-roadmap.js`, `ai-roadmap-map.js`

채용공고를 주 1회 수집해 직무별 요구 역량을 뽑고, 훈련생이 이미 학습한 것과 비교해
"다음에 뭘 채워야 하는지"를 단계로 보여준다.

- **지도로 그린 이유** — 단계를 목록으로 세우면 "어디까지 왔는지"가 안 보인다.
  길 위의 지점으로 그리고 `done / current / locked` 세 상태만 쓴다.
- **원문 공고를 같이 보여준다** — 판단 근거를 감추지 않는다. 수집일을 항상 표시.
- **시연 데이터** — 외부 회사명·공고는 실제 수집 결과가 들어올 자리라 가상 이름.
  단, **원내 과정명은 실제 개설 과정**(클라우드 인프라 입문 AWS 등)과 맞춰 뒀다.

**실데이터로 바꾸려면** 수집기(주 1회 배치) → 공고 저장 → 직무별 역량 추출(AI) →
훈련생 이수 이력과 대조. 화면 코드는 손대지 않아도 된다.

## 기능 2 — 학습 데이터 기반 맞춤 커리큘럼 추천

**화면** `/trainee/ai/curriculum` · **코드** `static/js/trainee/ai-curriculum.js`

진도·평가·출결로 약한 영역을 찾고, 그 영역을 메워 줄 **원내 과정**을 추천 이유와 함께 제시.

- **외부 강의를 섞지 않는다** — 훈련기관 LMS 가 외부 강의를 권하면 훈련생이
  어디서 신청하는지 알 수 없다.
- **이유를 문장으로 붙인다** — 이유 없는 추천은 광고로 읽히고 안 누른다.
- **못 듣는 과정도 숨기지 않는다** — "왜 지금은 아닌지"를 알려준다.
- **시연 데이터** — 평균 진도율 55%는 대시보드 트랙에 찍히는 **실제 값과 같게** 맞췄고,
  추천 과정은 **실제 모집중 과정 2개**다. 누르면 실제로 신청할 수 있어야 말이 된다.

**실데이터로 바꾸려면** 진도·성적·출결 집계 → 취약 영역 산출 → 모집중 과정과 매칭.

## 기능 3 — AI Q&A ✅ 동작

**화면** `/trainee/ai/qna` · **코드** `ai/service/AiQnaService.java`, `ai/client/ClaudeAiClient.java`,
`web/trainee/ai/TraineeAiController.java`, `static/js/trainee/ai-qna.js`

강사 답변을 기다리지 않고, 그 과정의 학습 자료를 근거로 즉시 답한다.

### 흐름
```
화면(fetch) → POST /trainee/ai/qna/ask
            → AiQnaService  ── 권한·입력·자료 검사 (모델 호출 전) ──┐
            → AiClient ──→ Claude Messages API                    │ 하나라도 걸리면
            → 인용한 자료만 링크로 붙여 반환                        ┘ 모델을 부르지 않는다
```

### 돈이 새지 않게 막은 것 — 모델을 부르기 *전에* 검사
| 검사 | 안 막으면 |
|---|---|
| 수강(승인·수료) 중인 과정인가 | 남의 과정 커리큘럼이 답변으로 샌다 |
| 질문이 비었나 / 1000자 넘나 | 본문 통째로 붙여넣는 호출에 토큰이 나간다 |
| 그 과정에 학습 자료가 있나 | 근거 없이 지어낼 여지가 생긴다 |
| 하루 한도 (전체 500 / 1인 50) | 무한 루프 한 번에 요금이 터진다 |

### 거짓말하지 않게 막은 것
- **답변이 실제로 인용한 자료만** 링크로 붙는다. 인용 안 한 자료는 근거가 아니다.
- 범위 밖 번호(`[자료 9]`인데 자료가 1개)는 버린다 — 없는 링크는 404 로 간다.
- 표기를 "근거 자료" → **"관련 학습 자료"**로. 지금은 자료의 *제목·설명*만 모델에 넘기고
  영상 자막·문서 본문은 안 읽는다. 본문을 안 읽은 답을 "근거"라 부르면 과신한다.
- 프롬프트에서 **모르면 모른다고 말하게** 못 박았다. 지어낸 답이 제일 위험하다.
- 화면의 예시 답변을 지웠다 — 더미가 남아 있으면 **모델이 죽어도 그럴듯한 답이 나와**
  장애를 못 알아챈다.

### 실패해도 화면은 살아 있다
모델 장애·한도 초과도 `200 + 안내 문구`로 내려준다. 채팅창에서 500 이 나면
사용자에게 보여줄 말이 없다. 실패 여부는 본문의 `ok` 로 구분한다.

### API 키
저장소에 넣지 않는다. **환경변수 또는 `.env`(커밋 제외)로만** 주입.
키가 없으면 앱은 정상 기동하고 AI 기능만 꺼진 채 화면에 안내 배너가 뜬다.

```
LMS_AI_ENABLED=true
ANTHROPIC_API_KEY=...
LMS_AI_MODEL=claude-sonnet-5
```

**테스트** `AiQnaServiceTest` 7건 — 모델을 실제로 부르지 않는다. 테스트가 API 를 때리면
돈이 나가고 결과도 매번 달라져 실패를 믿을 수 없게 된다.

## 기능 4 — 학습진단 → 추가 과제 배부

**화면** `/instructor/ai/diagnosis` · **코드** `static/js/instructor/ai-diagnosis.js`

기능 3에서 훈련생이 남긴 질문 + 평가·과제 결과 → 취약 영역 진단 → 보완 과제 **제안**.

- **AI 는 배부하지 않는다** — 추천은 제안일 뿐이고 확정은 강사가 한다.
  훈련생에게 과제가 늘어나는 일을 모델이 자동으로 결정하면 되돌릴 사람이 없다.
- **주제를 개인보다 위에 둔다** — 여러 명이 같은 곳에서 막히면 개인 문제가 아니라
  **수업에서 덜 다뤄진 것**이다.
- **근거를 반드시 같이 보여준다** — 근거 없이 "보완 필요"라고만 하면 강사가 판단할 수 없다.
- 체크 → [추천 과제 배부하기] → 평가관리 > 과제채점 > 과제 배정으로 대상자를 실어 보낸다.
  여러 명의 추천 과제가 다르면 같은 과제끼리만 묶어 넘긴다(배정 화면이 과제 하나를 다룸).
- **시연 데이터** — 훈련생 이름을 **실제 시드 계정**과 같게 맞췄고(이훈련·김서연·박도윤·
  이하은·정민준·최지우·한소율), 취약 주제도 **실제 등록된 학습 자료 6종(1~6주차) 범위
  안에서만** 쓴다. 자료에 없는 주제를 진단해 봐야 보완할 자료가 없다.

## 기능 5 — 대시보드

### ✅ 실데이터 부분
| 항목 | 출처 |
|---|---|
| 과정별 진도율 · 기간 경과율 | `DashboardMetricsService` → `dashboard-charts-common.js` |
| 이수 요건 충족 인원 | `CompletionService` |
| 훈련생 순위 트랙("우리 반에서 내 위치") | `DashboardMetricsService.paceOf()` → `CoursePaceView` |
| 강사 처리할 일 체크리스트 | `InstructorDashboardService` |

**관리자와 강사가 같은 그림을 본다** — 보는 범위만 다르고 계산은 같다.
예전엔 강사 쪽에만 표본 폴백이 남아 있어 같은 과정을 두고 서로 다른 숫자를 봤다.

**없는 값을 지어내지 않는다**
- 기간 경과율 `elapsed < 0` = "기준선을 계산할 수 없음" → 기준선을 아예 안 그린다.
  0 이나 100 으로 그리면 거짓 정보가 된다.
- 이수 판정 이력이 없으면 빈 목록. 판정 전 인원을 미충족으로 세면 실제보다 나쁘게 보인다.
- 서버 값이 없으면 아무것도 안 그린다.

**순위 트랙** — 성적이 아니라 **진도**로 줄 세운다. 성적은 위화감이 생기고 확정 전 값이
섞일 수 있다. 진도는 오늘 바로 바꿀 수 있다. 다른 훈련생의 **이름은 쓰지 않는다.**

### ⚠ 시연용 부분
`static/js/ai-widget.js` — 각 역할 첫 화면의 AI 기능 입구 카드.

- **훈련생** : 숫자가 아니라 **행동**. "충족도 62%"만 있으면 보고 나서 뭘 할지 모른다.
  무엇을 해주는지 한 줄 + 누를 버튼 하나.
- **강사** : 처리할 일. 각 카드가 진단 화면의 해당 구간으로 바로 간다.
- **관리자** : 링크 없이 값만 — 당장 처리할 일이 아니라 추세를 보는 값이다.

건수는 기능 3·4 화면과 **같은 값**을 쓴다. 대시보드에서 63건이라 하고 들어가면
186건이면 아무도 안 믿는다.

## 시연 데이터를 만든 원칙

정부 제출·시연에서 **화면끼리 말이 어긋나면** 전체를 못 믿게 된다. 그래서 시연용
데이터도 다음을 지켰다.

1. **사람 이름은 실제 시드 계정만** — 화면에 없는 사람이 나오면 과제를 배부하려 할 때
   대상자를 못 찾는다.
2. **과정명은 실제 개설 과정만** — 추천을 눌렀는데 없는 과정이면 신청할 수 없다.
3. **주제는 실제 등록된 학습 자료 범위 안에서만** — 자료에 없는 주제를 취약하다고 하면
   공부할 곳이 없다.
4. **같은 값은 화면마다 같게** — 진도율 55%, AI 질문 63건 등.
5. **실데이터와 시연 데이터를 화면에서 구분** — 관리자 Q&A 화면은 실제 Q&A 목록과
   AI 현황 패널을 나눠 뒀다.

로컬 시연 데이터를 만드는 곳:
- `course/LocalProgressDemoDataInitializer` — 진도율·수강생 6명 채우기
- `ai/LocalAiMaterialDemoInitializer` — 학습 자료 6종(1~6주차)

둘 다 `@Profile("local")` — **운영에서는 돌지 않는다.**
